# Hop3 Demo 2 - Docker Deployment

This demo demonstrates deploying a Docker-based application with Hop3.

## Purpose

The demo showcases:

1. Building Docker images from a Dockerfile
2. Deploying containers with Docker Compose
3. Routing traffic through nginx proxy to containers
4. Managing Docker-based applications with Hop3 CLI

## Prerequisites

- **Hop3 installed**: Run demo1 first on a fresh server, or ensure Hop3 is already installed
- **Docker**: Will be installed automatically if not present
- **Local Machine**:
  - Python 3.10+
  - Hop3 CLI installed (`pip install hop3-cli`)
  - SSH key authentication configured for the target server

## Usage

### Basic Usage

```bash
python demo.py <server_ip>
```

Example:
```bash
python demo.py 46.62.169.221
```

### Options

```bash
python demo.py <server_ip> [options]

Options:
  --ssh-user USER       SSH user (default: root)
  --admin-user USER     Admin username (default: admin)
  --admin-email EMAIL   Admin email (default: admin@example.com)
  --admin-password PWD  Admin password (default: randomly generated)
  --app-hostname HOST   Hostname for the demo app (default: a2.hop.demo)
  --no-cleanup          Don't destroy the demo app at the end
  --pause SECONDS       Pause between steps (default: 0.5)
```

### Examples

```bash
# Full demo (requires Hop3 to be installed already)
python demo.py 46.62.169.221

# Keep the demo app running after the demo
python demo.py 46.62.169.221 --no-cleanup

# Custom hostname
python demo.py 46.62.169.221 --app-hostname docker.example.com

# Slower pacing for screencasts
python demo.py 46.62.169.221 --pause 2
```

## Application Structure

```
hello-docker/
├── app.py              # Flask application code
├── requirements.txt    # Python dependencies
├── Dockerfile          # Container image definition
└── hop3.toml          # Hop3 configuration
```

**Note:** Hop3 generates `docker-compose.yml` automatically based on the Dockerfile.
For advanced use cases (multi-container, volumes, networks), you can provide your own compose file.

### Key Files

**Dockerfile** - Defines how to build the container image:
```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE 8080
CMD ["gunicorn", "app:app", "--bind", "0.0.0.0:8080"]
```

**hop3.toml** - Tells Hop3 to use the Docker builder:
```toml
[build]
builder = "docker"
```

### Generated docker-compose.yml

Hop3 automatically generates a compose file like this:
```yaml
# Generated by Hop3
services:
  web:
    image: ${HOP3_IMAGE_TAG}
    ports:
      - "127.0.0.1:${PORT:-8080}:8080"
    environment:
      - PORT=8080
    restart: unless-stopped
```

## How It Works

1. **Upload**: Hop3 CLI uploads the application files to the server
2. **Build**: Hop3 detects `builder = "docker"` and runs `docker build`
3. **Deploy**: Hop3 uses Docker Compose to start the container
4. **Proxy**: Nginx is configured to route traffic to the container
5. **Manage**: Use Hop3 CLI to restart, scale, or destroy the application

## Comparison with Demo 1

| Aspect | Demo 1 (uWSGI) | Demo 2 (Docker) |
|--------|----------------|-----------------|
| Runtime | Python virtualenv + uWSGI | Docker container |
| Build | pip install | docker build |
| Config | requirements.txt | Dockerfile + compose |
| Isolation | Process-level | Container-level |
| Portability | Python-specific | Any language/runtime |

## Troubleshooting

### Docker Not Running

If Docker is not installed or running:
```bash
# Install Docker (Ubuntu)
apt-get install docker.io

# Start Docker
systemctl enable docker
systemctl start docker

# Add hop3 user to docker group
usermod -aG docker hop3

# Restart hop3-server to pick up new group membership
systemctl restart hop3-server
```

### Permission Denied

If hop3 user cannot access Docker (permission denied on docker.sock):
```bash
# Add to docker group
usermod -aG docker hop3

# IMPORTANT: Restart hop3-server to pick up new group membership
# The running process won't see the new group until restarted
systemctl restart hop3-server
```

### Container Fails to Start

Check the container logs:
```bash
# On the server
su - hop3
docker logs hello-docker-web-1
```

### Port Conflicts

If port 8080 is already in use, Hop3 will allocate a different port automatically.
